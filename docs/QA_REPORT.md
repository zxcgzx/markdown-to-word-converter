## 已修复的结构问题

### 多卡片堆叠

文件、文档名、视图和输出不再各自表现为厚重卡片，而是处于一块连续操作面中，通过轻量分隔线表达关系。

### 旧缓存导致行布局回退

新增后加载的 `toolbar.css`，并对关键行使用明确的全宽与布局覆盖；资源地址加入 `?v=5.1.2`，减少旧 CSS 继续生效的概率。

### 平板左侧纵向堆栈

681～900 像素改为两列两行命名网格，打开和 Word 位于第一行，文档名与视图位于第二行，空间分布更均衡。

### 文档名缺少主次

文档名成为中间可伸缩区域，并增加文档图标、扩展名胶囊和聚焦反馈，与普通操作按钮明显区分。

### 隐藏操作不完整

“更多”中补入保存 Markdown与复制富文本，并继续包含公式、表格、AI、清空和设置；菜单关闭时完全退出布局。

## ZIP 与解压复测

最终发布包应包含一个顶层目录：

```text
markdown-to-word-converter-fusion-v5.1.2/
```

打包流程：

1. 移除旧版本截图和临时文件；
2. 运行 55 项 Node 测试；
3. 运行四个 JavaScript 文件语法检查；
4. 执行 HTML、CSS 和本地资源静态检查；
5. 创建 ZIP 并执行压缩数据完整性检查；
6. 解压到全新临时目录；
7. 在解压副本重新运行测试、语法检查和静态检查；
8. 生成独立 SHA-256 校验文件。

## 部署后仍需人工确认

1. GitHub Pages 或本地网络能够加载全部 CDN；
2. 浏览器缩放 90%、100%、110%、125% 时工具栏符合个人使用习惯；
3. 用目标版本 Microsoft Word 或 WPS 打开真实导出的 DOCX；
4. 复杂分式、矩阵和多行公式仍是线性可编辑文本，不是 OMML；
5. 网络图片读取受来源服务器和浏览器跨域策略影响；
6. AI 请求受实际接口、模型、API Key、配额和 CORS 影响。
