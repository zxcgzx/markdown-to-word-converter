# v5.1.1 质量检查报告

## 结论

v5.1.1 针对顶部工具栏拥挤与不可点击问题完成结构性修复。在本次 **53 项 Node 自动测试、110 项浏览器回归、JavaScript 语法检查、HTML/CSS 静态检查、ZIP 完整性检查与解压后复测** 的覆盖范围内，未发现已知阻断性问题。

有限测试不能证明任何前端项目绝对不存在缺陷，因此本报告同时列出自动化覆盖边界和部署后仍需人工确认的项目。

### 浏览器测试方法边界

自动化环境使用项目真实 HTML、CSS 与本地 JavaScript，并为 Marked、DOMPurify、KaTeX、docx.js 和 FileSaver 提供确定性依赖桩。它能够验证布局、点击命中、DOM 交互与应用控制逻辑，但不等同于：

- 实际 CDN 可用性测试；
- KaTeX 字形的像素级视觉测试；
- Microsoft Word 或 WPS 打开真实 DOCX 的端到端测试；
- 真实 AI 服务商网络请求测试。

## 已修复问题

### 单行过载

旧布局把文件、文档名、编辑、AI、清空、视图和输出塞进同一行，控件总宽度超过可用空间。新版拆成两行，降低每一行的密度。

### 输出区域遮挡

旧输出组依赖右侧 `sticky`，在部分宽度下会覆盖相邻视图按钮。新版将输出组改回正常 CSS Grid 项，不再覆盖。

### 点击目标过小

格式按钮和普通工具按钮统一扩大高度，并增加焦点环，减少误点与无法命中的情况。

### 窄屏功能消失

低频能力不再静默隐藏，而是进入“更多”；手机端则主动只保留完成主任务所需的五个控件。

### 更多菜单拦截点击

关闭状态下的弹出层被明确设为 `display: none`，不会在不可见时占位或拦截指针。打开后限制高度并允许内部滚动。

## ZIP 与解压复测

最终发布包应包含一个顶层目录：

```text
markdown-to-word-converter-fusion-v5.1.1/
```

打包流程包括：

1. 移除临时浏览器测试页面；
2. 运行 53 项 Node 测试；
3. 运行四个 JavaScript 文件语法检查；
4. 创建 ZIP 并执行压缩数据完整性检查；
5. 解压到全新临时目录；
6. 在解压副本中重新运行测试与语法检查；
7. 生成独立 SHA-256 校验文件。

## 部署后仍需人工确认

1. GitHub Pages 或本地网络能够加载全部 CDN；
2. 常用浏览器缩放比例下工具栏仍符合个人习惯；
3. 用目标版本 Microsoft Word 或 WPS 打开真实导出的 DOCX；
4. 复杂分式、矩阵和多行公式仍是线性可编辑文本，不是 OMML；
5. 网络图片读取受来源服务器和浏览器跨域策略影响；
6. AI 请求受实际接口、模型、API Key、配额和 CORS 影响。
