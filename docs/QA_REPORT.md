### 浏览器测试方法说明

自动化环境会阻止 Chromium 直接访问外部 CDN和本地 HTTP 服务。因此浏览器回归使用项目原始 HTML、CSS 与本地 JavaScript，并为 Marked、DOMPurify、KaTeX、docx.js、FileSaver 提供确定性依赖桩。

这能够验证真实应用控制逻辑、DOM 交互、响应式布局、公式源码位置、导出状态和 DOCX 参数构造，但不等同于：

- 真实 CDN 可用性测试；
- KaTeX 字形视觉像素级测试；
- Microsoft Word 或 WPS 实际打开 DOCX 的端到端测试；
- 真实 AI 服务商网络请求测试。

## 本轮发现并修复的问题

### 设置与移动端

- 修复 Word 页边距 `2.54` 与旧 `step=0.1` 冲突，导致设置无法保存或关闭；
- 设置关闭按钮显式改为普通按钮动作；
- 补齐 `.visually-hidden`，防止隐藏标签占据移动端工具栏空间。

### 公式定位

- 松散 `[ ... ]` 修复改为保留原始空白，只插入反斜杠；
- 新增标准化源码到原始源码的偏移映射；
- 多个松散公式分别保留自己的精确范围；
- 修复松散公式 KaTeX 失败时错误选中相邻内容的问题。

### 代码围栏与位置计算

- 修复带尾随正文的围栏标记被错误识别为关闭围栏；
- 修复全局错误的空偏移被错误转换为字符 0；
- 修复行内代码包含 emoji 时 UTF-16 偏移漂移。

### 稳定性与可访问性

- 本地存储读写增加异常保护；
- 视图按钮同步维护 `aria-pressed`；
- 核心解析器缺失时生成不可定位的明确阻断项；
- 通用 AI 请求移除非所有兼容接口都接受的强制参数。

## 已知边界与部署后人工验收

仍需在实际使用环境确认：

1. GitHub Pages 或本地网络能够加载全部 CDN 依赖；
2. 用目标版本 Microsoft Word 或 WPS 打开真实导出的 DOCX；
3. 复杂分式、矩阵、积分与多行公式当前仍是线性可编辑文本，不是 OMML；
4. 网络图片能否读取受来源服务器和浏览器跨域策略影响；
5. AI 请求受实际接口、模型、API Key、配额和 CORS 影响；
6. 极长文档在低性能手机上的实时渲染仍建议人工观察。
