## 2. 发布前发现并修复的问题

### 2.1 文件选择器 Live FileList

浏览器的 `FileList` 可能是实时对象。如果先清空文件输入框，再异步读取 `event.target.files`，文件列表会同时变空。

修复后先执行：

```js
const files = Array.from(event.target.files || []);
event.target.value = '';
```

再导入图片，并增加回归测试。

### 2.2 文档末尾和连续分页

最初页面估算会丢失文档末尾分页符产生的空白下一页，也会合并连续分页。

修复后：

- 末尾分页保留空白页；
- 连续分页分别生成页面；
- A4 预览和 Word `PageBreak` 行为保持一致。

### 2.3 Word 图片超过可打印宽度

最初图片只按素材尺寸生成，可能超过横向或窄边距页面的可打印区域。

修复后通过当前纸张、方向和四边页边距计算打印宽度，并限制 `ImageRun` 宽度。

### 2.4 重复动作委托

图片、模板、分页和刷新由独立模块接管后，旧的通用委托仍可能重复响应。

修复后每个动作只有一个明确处理者，浏览器集成测试确认单击“分页”只插入一次。

### 2.5 v5.3 数据迁移键不一致

开发版最初只兼容了一个早期测试键，没有读取正式 v5.3 使用的：

```text
md2word-workspace-v5.3
md2word.workflow.documents.v5.3
md2word.workflow.current.v5.3
```

发布前已补齐：

- 旧 IndexedDB 只读迁移；
- 正式 localStorage 文档映射迁移；
- 文档内嵌版本拆分到新版本存储；
- 光标、视图和最后打开文档迁移；
- 新数据优先，旧数据不覆盖同 ID v5.4 文档；
- 一次性迁移标记和兼容测试。

## 9. 仍需真实环境验收

自动化不能完全替代外部环境，部署后仍建议：

1. 在 GitHub Pages 中确认真实 CDN 能加载 Marked、DOMPurify、KaTeX、docx.js 和 FileSaver；
2. 用实际 Microsoft Word 或 WPS 打开包含中文、表格、图片、化学式、分页和横向页面的 DOCX；
3. 测试一个允许 CORS 的网络图片和一个禁止 CORS 的网络图片；
4. 使用自己的 AI 服务商、模型、API Key、配额和 CORS 环境完成一次请求；
5. 在常用浏览器中确认 IndexedDB、剪贴板、拖放和下载权限。

在上述自动测试覆盖范围内，未发现已知阻断性问题。任何前端应用都无法承诺绝对零缺陷；真实网络、浏览器策略、图片服务器和 Word/WPS 版本仍可能带来环境差异。
