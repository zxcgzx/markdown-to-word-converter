# 融合体验版 v5.1.2 更新与验收指南

## 一、本次更新解决什么

v5.1.2 在 v5.1.1 的双层工具栏基础上继续优化视觉结构，重点解决以下问题：

- 多个独立卡片并排后仍显得零散、厚重；
- 某些宽度或旧缓存下，文档行与编辑行可能再次左右并排；
- 平板宽度下容易形成左侧纵向堆叠，右侧留下大面积空白；
- 文档名、视图与输出之间缺少明确的视觉主次；
- 隐藏到“更多”的操作不够完整。

新版采用一块连续的 **Command Deck**：

```text
文档行：文件 | 文档名 | 视图 | 输出
编辑行：常用格式 | 表格 | AI 修复 | 更多 | 清空
```

文档名占据可伸缩区域，“下载 Word”仍是页面唯一高亮主按钮。工具栏不会依赖横向滚动，也不再使用覆盖相邻按钮的输出定位。

## 二、更新前准备

1. 记录当前仓库提交：

   ```bash
   git rev-parse HEAD
   ```

2. 下载重要内容的 `.md` 备份。
3. 备份自己修改过的 `js/access-config.js`。
4. 解压 v5.1.2 完整包。

v5.1.2 是完整静态项目，可直接覆盖，不要求先安装旧版本。

## 三、正确覆盖方式

压缩包包含顶层目录：

```text
markdown-to-word-converter-fusion-v5.1.2/
```

请把该目录中的**全部内容**复制到仓库根目录并覆盖同名文件。不要只替换 `index.html` 或 `css/app.css`，因为本版新增了独立工具栏样式并使用版本化资源地址。

核心运行文件：

```text
index.html
css/app.css
css/toolbar.css
js/access-config.js
js/math-engine.js
js/preflight.js
js/app.js
```

建议一起提交：

```text
README.md
CHANGELOG.md
LICENSE
package.json
tests/
docs/
.github/workflows/deploy.yml
```

## 四、为什么必须整体覆盖

v5.1.2 在 `index.html` 中按以下顺序加载样式：

```html
<link rel="stylesheet" href="css/app.css?v=5.1.2">
<link rel="stylesheet" href="css/toolbar.css?v=5.1.2">
```

`toolbar.css` 专门负责 Command Deck 的结构性覆盖，并在基础样式之后加载。本地脚本也带有 `?v=5.1.2`，用于减少 GitHub Pages 和浏览器继续使用旧缓存的概率。

只替换单个 CSS 文件会导致 HTML 结构、缓存参数和样式版本不一致。

## 六、工具栏专项验收

### 1. 1321 像素以上桌面端

预期：

- 工具栏是一块连续表面，而不是多个独立卡片堆叠；
- 第一行按文件、文档名、视图、输出排列；
- 文档名自动占用剩余宽度；
- 第二行占满宽度，格式工具从左开始，“清空”位于最右侧；
- “下载 Word”是唯一高亮主按钮；
- 页面无横向滚动，按钮之间无重叠。

### 2. 1181～1320 像素

预期：

- 文件、文档名、视图和 Word 主流程保持直接可见；
- 保存 Markdown、复制富文本等低频操作进入“更多”；
- “更多”关闭后完全退出布局，不拦截指针；
- 菜单打开后位于视口内，过长时可内部滚动。

### 3. 901～1180 像素窄桌面

预期：

- 顶部保留打开、文档名、视图和 Word；
- 编辑行只保留 H、B、I 与“更多”；
- 不出现文字叠加、按钮裁切或输出区遮挡视图。

### 4. 681～900 像素平板

预期文档区为平衡的两列两行：

```text
打开            下载 Word
文档名          视图切换
```

编辑行位于其下，不应形成截图中那种左侧长纵列和右侧大空白。

### 5. 680 像素及以下手机

预期顶部严格只保留：

```text
打开 · 编辑 · 分栏 · 预览 · Word
```

编辑工具行隐藏，页面与工具栏都不出现横向溢出。

### 6. 点击与键盘可达性

逐项确认：

- 打开、保存 Markdown、复制富文本；
- 编辑、分栏、预览；
- H、B、I、公式、表格、AI、更多、清空；
- 下载 Word。

控件中心和边缘均应正常响应。使用 Tab 键时应出现清晰焦点环。

## 七、核心功能回归

工具栏之外，请快速确认：

1. 密码入口、分享码、主题和退出正常；
2. 默认空白启动，本地草稿只提供恢复入口；
3. 文档名用于 `.md` 与 `.docx` 文件名；
4. 浏览器草稿保存与 Markdown 文件下载状态分开显示；
5. 公式诊断可定位到对应 Markdown 源码；
6. 导出前检查可定位公式、标题、表格、图片和链接问题；
7. 松散 `[ ... ]` 公式可写回标准 `\[ ... \]`；
8. 分栏拖动、同步滚动和大纲正常；
9. Word 中化学式和变量上下标保持可编辑；
10. 统一设置中的界面、Word、AI、快捷键和账户分类可切换。

## 九、提交到 GitHub

验收后执行：

```bash
git add .
git commit -m "Release v5.1.2 Command Deck toolbar"
git push origin main
```

`.github/workflows/deploy.yml` 会在 `main` 更新后继续发布 GitHub Pages。

## 十、部署后人工确认

1. GitHub Pages 中 `app.css?v=5.1.2` 与 `toolbar.css?v=5.1.2` 均成功加载；
2. 常用桌面宽度和浏览器缩放比例下工具栏符合个人习惯；
3. 约 800 像素宽度下呈现平衡 `2 × 2` 布局；
4. 手机端没有横向溢出；
5. 用实际 Microsoft Word 或 WPS 打开一次包含化学式的 DOCX；
6. 使用自己的 AI 服务商、模型和 API Key 完成一次真实请求。

## 十一、回退

```bash
git reset --hard <更新前提交>
```

建议整套回退，不要混用 v5.1.2 的 HTML、`toolbar.css` 与旧版脚本。
