# 融合体验版 v5.1 更新与验收指南

## 一、更新前准备

1. 记录当前仓库提交：

   ```bash
   git rev-parse HEAD
   ```

2. 在旧页面主动下载一次重要内容的 `.md` 备份。
3. 备份自己修改过的 `js/access-config.js`。
4. 记录 AI 服务商、接口、模型和 API Key。浏览器中已有配置通常仍会保留，但不应只依赖浏览器存储作为唯一备份。
5. 解压 v5.1 完整包。

v5.1 是可独立运行的完整静态项目，不需要先安装 v5，也不依赖旧版 CSS 或 JavaScript。

## 二、正确覆盖方式

将压缩包顶层目录中的全部内容复制到仓库根目录，覆盖同名文件。核心运行文件为：

```text
index.html
css/app.css
js/access-config.js
js/math-engine.js
js/preflight.js
js/app.js
```

配套文件也建议一并提交：

```text
README.md
CHANGELOG.md
LICENSE
package.json
tests/
docs/
.github/workflows/deploy.yml
```

不要只替换 `index.html` 或单个脚本。HTML、CSS、公式引擎、导出检查和应用逻辑是同一版本，需要整套更新。

## 三、密码与会话

密码配置位于：

```text
js/access-config.js
```

默认密码：

```text
basic123  → 基础用户
517517    → 高级用户
lingling  → 超级管理员
```

三个身份均可使用完整核心能力，等级只用于入口与显示。

v5.1 会话键为：

```text
md2word.fusion.auth.v5.1
```

从 v5 或更早版本更新后需要重新登录一次。同一会话内刷新页面会继续保持登录；退出后重新显示密码页。

## 四、浏览器数据与草稿

v5.1 默认空白启动。本地存在草稿时，空预览会显示“恢复草稿”，也可在设置中开启启动自动恢复。

本版将视图偏好拆分为：

```text
md2word.personal.view.desktop.v5.1
md2word.personal.view.mobile.v5.1
```

因此桌面和手机不会互相覆盖视图模式。旧版视图设置不会直接污染 v5.1 的首次体验。

浏览器存储与域名、协议和端口绑定。从 GitHub Pages 切换到本地地址，或更换本地端口，都会被浏览器视为另一套存储空间。

## 五、v5.1 重点验收

### 1. 密码入口和原版视觉

- 页面首先显示密码入口；
- 密码显示切换、Enter 登录和分享码粘贴可用；
- 登录后显示正确身份；
- 四套主题可循环切换；
- 退出后回到密码入口。

### 2. 常驻顶部工作流

- 顶部操作栏按“文件、编辑、视图、输出”分组；
- 页面只有一个高亮主按钮：“下载 Word”；
- 页面向下滚动后操作栏仍保持可见；
- 顶部文档名可编辑，并显示 `.md / .docx` 用途。

### 3. 保存状态区分

进行一次编辑后观察状态：

- 自动保存完成应显示浏览器草稿状态；
- 点击“保存 .md”后应单独显示 Markdown 文件下载状态；
- 两者文案不能混为“已保存”。

### 4. 公式精确定位

粘贴：

```latex
# 公式检查

\[
\badcommand{x}
\]
```

预期：

- 公式状态显示一个渲染错误；
- 点击公式状态展开诊断；
- 点击“定位源码”后，编辑器选中完整公式块；
- 状态栏报告对应行列；
- 点击预览中的红色错误公式也可得到相同结果。

再测试松散边界：

```text
[
\text{玻片–O–Si–(CH}_2)_3
]
```

预期：

- 计入边界修复；
- 定位范围只覆盖原始方括号块；
- 点击标准化后写回 `\[ ... \]`；
- 原有缩进和空行保持不变。

### 5. 导出前检查

依次测试：

```markdown
# 一级标题

### 直接跳到三级标题
```

预期：

- Word 按钮出现提醒徽标；
- 首次点击 Word 不直接下载，而是打开“导出前检查”；
- 检查项包含定位按钮；
- 定位后选中对应三级标题源码；
- 清理问题后按钮恢复检查通过状态；
- 也可以在检查面板明确选择“仍然导出”。

再测试未闭合公式：

```latex
\[
x_1 + x_2
```

预期为阻断错误，而不是普通提醒。

### 6. 文档名

- 打开名为 `实验报告.md` 的文件后，文档名显示“实验报告”；
- 修改为“最终报告”；
- 下载 Markdown 得到 `最终报告.md`；
- 下载 Word 得到 `最终报告.docx`；
- 非法文件名字符会被安全替换。

### 7. 窄桌面“更多”菜单

将浏览器宽度调整到约 900 像素：

- 高频工具保持可见；
- 低频格式和工具进入“更多”；
- 不应出现工具静默消失且无替代入口的情况；
- 点击页面其他区域后菜单关闭。

### 8. 分类设置

- 页面只有一个设置对话框；
- 界面、Word、AI、快捷键和账户分类可切换；
- 左右方向键可在分类标签间移动；
- 将 Word 页边距设置为 `2.54 cm` 后可保存并重新打开确认；
- 保存或关闭设置时不应被浏览器表单校验卡住。

### 9. 桌面与手机视图独立

- 桌面选择“预览”，刷新后仍记忆；
- 缩窄到 390 像素，首次手机视图应为“编辑”；
- 手机选择其他视图后单独记忆；
- 再回到桌面，桌面视图不应被手机设置覆盖。

### 10. 移动端

在约 390 × 844 的视口中：

- 顶部只显示打开、编辑、分栏、预览和下载 Word；
- 页面和操作栏都没有横向滚动；
- 账户、主题和低频操作不会挤占顶部；
- 底部“设置与账户”入口可用。

### 11. Word 公式一致性

使用以下内容导出：

```latex
\[
\text{玻片–O–Si–(CH}_2)_3\text{–S–S–(CH}_2)_2
\]
```

用目标版本的 Microsoft Word 或 WPS 打开后检查：

- 数字 `2`、`3` 使用可编辑下标运行；
- 文档不包含“请手动添加公式”占位提示；
- 文字仍可选中和修改；
- 复杂分式与矩阵会收到线性化提醒，它们目前不是 OMML 原生公式。

## 六、本地运行

在项目根目录运行：

```bash
python -m http.server 8000
```

访问：

```text
http://localhost:8000
```

页面依赖 CDN 加载 Marked、DOMPurify、KaTeX、docx.js 和 FileSaver。真实部署验收时应确认当前网络能够访问这些资源。

## 七、自动检查

```bash
npm test
npm run check
```

当前预期：

```text
47 tests passed
0 tests failed
JavaScript syntax checks passed
```

测试使用 Node.js 内置测试运行器，不需要安装第三方 npm 包。

## 八、提交到 GitHub

验收后执行：

```bash
git add .
git commit -m "Release v5.1 export preflight and formula source location"
git push origin main
```

`.github/workflows/deploy.yml` 会在 `main` 更新后发布 GitHub Pages。

## 九、部署后必须人工确认

自动测试无法替代以下真实环境检查：

1. GitHub Pages 上所有 CDN 依赖均成功加载；
2. 下载真实 DOCX，并用你实际使用的 Word 或 WPS 打开；
3. 使用自己的服务商、模型和 API Key 发起一次真实 AI 请求；
4. 在你常用的桌面浏览器与手机浏览器各完成一次基本流程。

## 十、回退

需要回退时恢复更新前的 Git 提交或完整备份目录：

```bash
git reset --hard <更新前提交>
```

建议整套回退，不要混用 v5.1 的 HTML、v5 的 CSS 和旧版 JavaScript。
