# 融合体验版 v5 更新指南

## 一、更新前准备

1. 备份当前仓库或记录当前提交：

   ```bash
   git rev-parse HEAD
   ```

2. 在旧页面下载一次当前内容的 `.md` 备份。
3. 记录自己修改过的密码、AI 接口、主题或样式。
4. 解压 v5 更新包，将其中完整项目目录作为新版本使用。

v5 是可独立运行的完整静态项目，不依赖 v4 的旧 CSS、旧 JavaScript 或底部控制面板。

## 二、推荐覆盖方式

将解压目录中的全部内容复制到仓库根目录并覆盖同名文件。核心文件为：

```text
index.html
css/app.css
js/access-config.js
js/math-engine.js
js/app.js
```

建议同时提交：

```text
README.md
CHANGELOG.md
LICENSE
package.json
tests/
docs/
.github/workflows/deploy.yml
```

不要只替换 `index.html`。页面结构、样式、交互和公式引擎是同一版本，需要整套覆盖。

## 三、密码与登录状态

密码配置位于：

```text
js/access-config.js
```

默认密码：

```text
basic123  → 基础用户
517517    → 高级用户
lingling  → 超级管理员
```

三个身份均可使用完整功能，等级只用于身份展示。

v5 使用新的会话键：

```text
md2word.fusion.auth.v5
```

因此从 v4 更新后需要重新登录一次，这是正常现象。退出按钮也已整合到统一设置中，桌面端标题区仍保留快捷退出。

## 四、草稿与浏览器数据

v5 默认空白启动，即使浏览器里存在自动保存草稿，也不会自动写入编辑器。检测到草稿时，空预览区会提供“恢复草稿”按钮。

需要恢复旧行为时：

```text
设置 → 界面与草稿 → 启动时自动恢复草稿
```

同一域名下的草稿、界面偏好和 AI 配置通常仍可读取。浏览器存储与域名和端口绑定，切换 GitHub Pages 地址、本地域名或本地端口后，会被视为新的存储空间。

## 五、11 项重点验收清单

### 1. 常驻主操作

- 登录后顶部操作栏应始终贴在视口顶部。
- 页面只有一个高亮主按钮：“下载 Word”。
- 向下滚动后仍可直接点击导出。

### 2. 分组层级

顶部应依次看到：

```text
文件 | 编辑 | 视图 | 输出
```

“打开、保存 Markdown”归文件；格式、表格、AI 归编辑；模式与同步滚动归视图；复制和 Word 归输出。

### 3. 空白启动

- 首次进入编辑器为空白。
- 空预览中显示“打开文件”“加载公式示例”。
- 浏览器存在草稿时才额外显示“恢复草稿”。

### 4. 大纲替代缩略图

- 页面不应出现悬浮缩略导航或“找回缩略导航”。
- 预览标题栏右侧应有“大纲”下拉框。
- Markdown 包含标题时，选择条目应跳转到对应预览位置。

### 5. 可拖动分栏

- 拖动编辑与预览之间的分隔条，宽度应实时变化。
- 刷新后比例应被记忆。
- 双击分隔条应恢复均分。

### 6. 同步滚动

- 顶部“同步滚动”可随时开启或关闭。
- 开启后，左右区域按滚动比例联动。
- 只在分栏模式生效，避免单栏视图产生意外跳动。

### 7. 公式诊断

粘贴以下内容：

```latex
# 审核结论

在化学逻辑上是可以成立的，目标结构如下：

\[
\text{玻片–O–Si–(CH}_2)_3\text{–S–S–(CH}_2)_2\text{–NH–CO–C(Br)(CH}_3)_2
\]

\[
\badcommand{x}
\]
```

预览标题栏应显示类似：

```text
公式 2 · 错误 1 · 修复 0
```

点击状态后应看到具体错误和原始公式，错误公式仍以可见源码回退。

再测试退化形式：

```text
[
\text{玻片–O–Si–(CH}_2)_3
]
```

开启“修复独立 `[ … ]` 公式边界”时，应计入修复数量，并可写回标准 `\[ ... \]`。

### 8. 精简反馈

- 保存、复制、视图切换等普通反馈只出现在底部状态栏。
- 页面不应显示“今日剩余”、配额或权限额度。
- 只有真实失败才出现错误 Toast。

### 9. 单一设置窗口

- 表格与 AI 点击后应在工作区内联展开。
- 页面只应有一个低频设置窗口。
- 主题、草稿、同步滚动、Word、AI、快捷键和账户均在统一设置内。

### 10. 移动端

将浏览器缩窄至约 390 像素：

- 顶部只应保留“打开、编辑/分栏/预览、下载 Word”。
- 不应出现横向滚动条。
- 底部应有“设置与账户”。

### 11. Word 公式一致性

- 点击“下载 Word”。
- 用 Word 或 WPS 打开。
- 化学式中的数字应使用可编辑下标运行。
- 文档中不应出现“请手动添加公式”占位提示。
- 复杂矩阵和分式目前会以线性可编辑文本保留，这不等同于原生 OMML 公式。

## 六、本地运行

在项目根目录运行：

```bash
python -m http.server 8000
```

浏览器访问：

```text
http://localhost:8000
```

页面依赖 CDN 加载 Marked、DOMPurify、KaTeX、docx.js 和 FileSaver，实际部署验收时应确认网络能够访问这些资源。

## 七、自动检查

```bash
npm test
npm run check
```

预期结果：

```text
21 tests passed
0 tests failed
```

`npm test` 使用 Node 内置测试运行器，不需要安装第三方 npm 依赖。

## 八、提交到 GitHub

验收后执行：

```bash
git add .
git commit -m "Add focused sticky workflow and formula-aware DOCX export"
git push origin main
```

`.github/workflows/deploy.yml` 会在 `main` 更新时发布到 GitHub Pages。

## 九、回退

需要回退时使用更新前的提交或备份目录。建议整套回退，不要混用 v4 的 HTML 与 v5 的 CSS 或 JavaScript。
