# 融合体验版 v5.1.1 更新与验收指南

## 一、这次更新解决什么

v5.1.1 是基于 v5.1 的工具栏专项修复版，重点解决顶部操作区“按钮过密、相互挤压、看得到但点不到”的问题。

新版将常驻工具栏拆成两层：

```text
第一层：文件 · 文档名 · 视图 · 输出
第二层：格式编辑 · 表格 · AI 修复 · 更多 · 清空
```

“下载 Word”仍是页面唯一主按钮；它不再通过右侧覆盖层固定，而是作为第一层的正常网格项，因此不会遮住视图切换或其他操作。

## 二、更新前准备

1. 记录当前仓库提交：

   ```bash
   git rev-parse HEAD
   ```

2. 下载一次重要内容的 `.md` 备份。
3. 备份自己修改过的 `js/access-config.js`。
4. 解压 v5.1.1 完整包。

v5.1.1 是完整静态项目，可直接覆盖，不要求先安装 v5 或 v5.1。

## 三、正确覆盖方式

把压缩包顶层目录中的全部内容复制到仓库根目录，覆盖同名文件。不要只替换 `index.html` 或 `css/app.css`，因为页面结构、样式与测试是配套版本。

核心运行文件：

```text
index.html
css/app.css
js/access-config.js
js/math-engine.js
js/preflight.js
js/app.js
```

建议一起提交：

```text
README.md
CHANGELOG.md
LICENSE
package.json
tests/
docs/
.github/workflows/deploy.yml
```



v5.1.1 **刻意沿用 v5.1 的会话与视图存储键**：

```text

```

因此从 v5.1 覆盖更新时，通常无需仅因为工具栏补丁重新配置主题、视图或 AI。浏览器会话是否继续有效仍取决于原会话是否存在以及是否主动退出。

## 五、工具栏专项验收

### 1. 1366 像素及以上桌面端

预期：

- 工具栏分成上下两行；
- 第一行依次为文件、文档名、视图和输出；
- 第二行显示格式、表格、AI 修复和清空；
- “下载 Word”是唯一高亮主按钮；
- “清空”位于第二行最右侧，与格式操作明显分离；
- 页面没有横向滚动；
- 任意可见按钮都不会被其他元素覆盖。

### 2. 1024～1180 像素窄桌面

预期：

- 第一行仍保留新建、打开、文档名、视图和 Word 下载；
- 低频编辑工具进入“更多”；
- “更多”菜单打开后位于视口内，内容过长时可在菜单内部滚动；
- 菜单关闭后不占据页面布局，也不拦截点击。

### 3. 681～900 像素平板或窄窗口

预期：

- “新建”隐藏，“打开”继续可见；
- 文档名、视图和 Word 下载仍能点击；
- 编辑行只保留最常用的 H、B、I 和“更多”；
- 不出现按钮文字叠在一起或输出按钮压住视图按钮。

### 4. 680 像素及以下手机

预期顶部只保留：

```text
打开 · 编辑 · 分栏 · 预览 · Word
```

编辑工具行完全隐藏，页面和工具栏都不应出现横向滚动。

### 5. 点击可达性

建议在常用浏览器中逐个点击：

- 新建、打开、保存 Markdown；
- 编辑、分栏、预览；
- H、B、I、公式；
- 表格、AI 修复、更多、清空；
- 复制富文本和下载 Word。

按钮边缘和中心位置都应正常响应；使用 Tab 键时应出现清晰焦点环。

## 六、v5.1 功能回归

工具栏改造之外，还应快速确认以下功能没有回退：

1. 密码入口、分享码、主题和退出；
2. 文档名用于 `.md` 与 `.docx` 文件名；
3. 浏览器草稿与 Markdown 下载状态分开显示；
4. 公式诊断可定位到 Markdown 源码；
5. 导出前检查可定位标题跳级、公式错误等问题；
6. 松散 `[ ... ]` 公式可写回标准 `\[ ... \]`；
7. 可拖动分栏、同步滚动和大纲下拉框正常；
8. Word 中化学式和变量下标保持可编辑。

## 七、本地运行与自动检查

在项目根目录运行：

```bash
python -m http.server 8000
```

浏览器访问：

```text
http://localhost:8000
```

然后执行：

```bash
npm test
npm run check
```

当前预期：

```text
53 tests passed
0 tests failed
JavaScript syntax checks passed
```

测试使用 Node.js 内置测试运行器，不需要安装第三方 npm 包。

## 八、提交到 GitHub

验收后执行：

```bash
git add .
git commit -m "Release v5.1.1 two-row toolbar layout fix"
git push origin main
```

`.github/workflows/deploy.yml` 会在 `main` 更新后继续发布 GitHub Pages。

## 九、部署后人工确认

1. GitHub Pages 上 CDN 依赖能够正常加载；
2. 你常用的 1366 或 1920 像素桌面宽度下按钮均可点击；
3. 约 1024 像素宽度下“更多”菜单没有超出视口；
4. 手机浏览器没有横向溢出；
5. 用实际 Word 或 WPS 打开一次包含化学式的 DOCX；
6. 使用自己的服务商、模型和 API Key 完成一次真实 AI 请求。

## 十、回退

需要回退时恢复更新前提交：

```bash
git reset --hard <更新前提交>
```

建议整套回退，不要混用 v5.1.1 的 HTML 与旧版 CSS。
